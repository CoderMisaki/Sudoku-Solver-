## 2023-10-27 - Restoring Keyboard Focus and Semantic Labels
**Learning:** In applications using utility-first frameworks or custom CSS resets, the default `outline` is often entirely removed (e.g., `outline: none;`), which completely breaks keyboard navigation visibility. Additionally, highly iconic UIs frequently neglect descriptive text for assistive tech.
**Action:** Always verify that interactive components (buttons, cells) have a `:focus-visible` state explicitly defined when `outline` is removed, and ensure all icon-only or abbreviation-only controls possess descriptive `aria-label`s.## 2024-06-25 - Dynamic Text Announcements via aria-live
**Learning:** In highly interactive single-page applications (SPAs), visual state changes (like status updates, step counters, and inline form errors) are often imperceptible to screen reader users unless focus changes or explicit ARIA regions are used. Without them, users are left unaware of critical application state changes.
**Action:** Always identify text nodes that change dynamically in response to user actions (e.g., status bars, error message containers, counters) and apply `aria-live="polite"` (or `"assertive"` for critical alerts) to their container to ensure screen readers announce the updates contextually.
