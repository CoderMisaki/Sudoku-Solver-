## 2023-10-27 - Restoring Keyboard Focus and Semantic Labels
**Learning:** In applications using utility-first frameworks or custom CSS resets, the default `outline` is often entirely removed (e.g., `outline: none;`), which completely breaks keyboard navigation visibility. Additionally, highly iconic UIs frequently neglect descriptive text for assistive tech.
**Action:** Always verify that interactive components (buttons, cells) have a `:focus-visible` state explicitly defined when `outline` is removed, and ensure all icon-only or abbreviation-only controls possess descriptive `aria-label`s.## 2024-06-23 - Focus Management in Custom Grid Components
**Learning:** When making custom `div`-based UI widgets (like grids) keyboard accessible, implement a roving tabindex pattern (dynamically toggling `tabIndex` between `-1` and `0`). Explicitly calling `element.focus({ preventScroll: true })` on the active element is required to correctly trigger native `:focus-visible` CSS rules, keep visual selection synced with screen readers, and prevent unintended jumping/scrolling behavior.
**Action:** Always pair `tabIndex` manipulation with programmatic `.focus({ preventScroll: true })` when building custom keyboard-navigable UI components.
