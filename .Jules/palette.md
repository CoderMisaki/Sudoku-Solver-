## 2023-10-27 - Restoring Keyboard Focus and Semantic Labels
**Learning:** In applications using utility-first frameworks or custom CSS resets, the default `outline` is often entirely removed (e.g., `outline: none;`), which completely breaks keyboard navigation visibility. Additionally, highly iconic UIs frequently neglect descriptive text for assistive tech.
**Action:** Always verify that interactive components (buttons, cells) have a `:focus-visible` state explicitly defined when `outline` is removed, and ensure all icon-only or abbreviation-only controls possess descriptive `aria-label`s.
## 2024-05-25 - ARIA Live Regions for Dynamic Text
**Learning:** In vanilla JavaScript SPA interfaces (like this Sudoku Solver), updating the `textContent` of a DOM element does not automatically notify screen readers, especially when visual focus remains elsewhere (e.g., on a clicked button or cell). The application heavily relies on dynamic `#status` and `#modal-error` messages for critical feedback (e.g., "Board full", "Clashing numbers", "No solution").
**Action:** Always verify that elements acting as status bars or error notifications have appropriate `aria-live` attributes (`polite` for non-interruptive status updates, `assertive` for critical errors) and semantic `role` attributes (`status` and `alert` respectively) to ensure accessibility parity with the visual experience.
