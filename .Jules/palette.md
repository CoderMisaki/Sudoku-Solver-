## 2023-10-27 - Restoring Keyboard Focus and Semantic Labels
**Learning:** In applications using utility-first frameworks or custom CSS resets, the default `outline` is often entirely removed (e.g., `outline: none;`), which completely breaks keyboard navigation visibility. Additionally, highly iconic UIs frequently neglect descriptive text for assistive tech.
**Action:** Always verify that interactive components (buttons, cells) have a `:focus-visible` state explicitly defined when `outline` is removed, and ensure all icon-only or abbreviation-only controls possess descriptive `aria-label`s.## 2024-05-20 - [ARIA Live Regions]
**Learning:** In vanilla JS SPAs with dynamic status text (like Sudoku error or navigation hints), screen readers require `aria-live` regions to detect changes without focus shifts. Using `aria-live="polite"` is best for general status, while `aria-live="assertive"` works well for errors.
**Action:** When evaluating forms and game elements that display temporary error states or changing hints, actively add `role="alert" aria-live="assertive"` to error containers and `role="status" aria-live="polite"` to hint elements.
