## 2024-05-24 - Accessibility: Roving Tabindex and Aria-Live
**Learning:** For a complex grid like a Sudoku board where arrow keys are used for navigation, standard DOM tabbing is inefficient. A roving `tabIndex` pattern (managing focus programmatically with arrow keys and toggling `tabIndex` between 0 and -1) combined with explicit `focus()` calls is required to make it accessible to keyboard users while preventing page jumps (`{ preventScroll: true }`). Screen readers also need status updates natively, which can be accomplished effectively by adding `aria-live="polite"` to status elements rather than relying on visual state alone.
**Action:** When implementing custom grid components with internal keyboard navigation, always implement the roving tabindex pattern. Ensure dynamic text areas that provide feedback get `aria-live` attributes to maintain parity between visual and auditory experiences.
