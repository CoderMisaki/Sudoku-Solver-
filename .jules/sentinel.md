## 2024-05-14 - Validate Untrusted Client-Side Storage
**Vulnerability:** The application blindly parsed and trusted `localStorage` data (`sudoku_lang` and `sudoku_board_state`) without verifying its structure or content.
**Learning:** Client-side storage (`localStorage`, `sessionStorage`, cookies) can be modified by the user or an attacker. If the application logic assumes specific structures (like nested arrays or keys in a dictionary) and encounters unexpected types, it leads to app-breaking exceptions (e.g., `TypeError` when accessing properties on undefined language data, or errors during array iteration).
**Prevention:** Always treat data retrieved from client-side storage as untrusted user input. Implement structural and type validation before assigning it to application state variables. Fail securely by falling back to safe defaults or discarding the corrupted state.
## 2025-06-21 - Added Strict Content Security Policy (CSP)
**Vulnerability:** The application completely lacked a Content Security Policy (CSP), making it vulnerable to Cross-Site Scripting (XSS) and unwanted resource injection if user-provided content were to be executed or rendered incorrectly.
**Learning:** For a simple vanilla HTML/JS application, adding a `<meta>` CSP tag is an effective defense-in-depth strategy. However, it requires specific configuration (like `'unsafe-inline'` for inline scripts/styles and allowing `data:` URIs for images) to prevent blocking the app's legitimate core functionality and resources (like Tailwind CSS).
**Prevention:** Always implement a baseline CSP as a standard security best practice for web applications, carefully tuning directives (`default-src`, `script-src`, `style-src`) to the specific architectural requirements of the app while testing rigorously to avoid breaking functionality.
